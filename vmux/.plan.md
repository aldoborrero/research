# vmux simplification plan

## Goal
Remove WezTerm pane management. Make `vmux run` the primary interface:
exec directly into the sandboxed/VM environment. Keep both backends.

## What changes

### 1. Delete vmux-wezterm crate
- Remove `crates/vmux-wezterm/` entirely
- Remove from workspace `Cargo.toml` members
- Remove dependency from vmux-core and vmux-cli Cargo.toml

### 2. Rewrite vmux-core
The BackendProvider trait stays but simplifies — no more pane commands.

**BackendProvider trait becomes:**
```rust
pub trait BackendProvider: Send + Sync {
    async fn prepare(&mut self, common: &CommonConfig, secrets: &[(String, SecretValue)]) -> Result<(), LaunchError>;
    fn wrap_command(&self, command: &str) -> Result<String, LaunchError>;
    async fn cleanup(&mut self) -> Result<(), LaunchError>;
}
```

**`launch_with_backend()` becomes:**
```
1. Resolve secrets
2. backend.prepare()
3. backend.wrap_command(tool_or_shell)
4. exec the wrapped command (replaces current process)
```

No more WezTerm session, no more `send_pane_commands()`, no more `wait_for_close()` polling.

**Remove from vmux-core:**
- `send_pane_commands()` function
- `status_info()` from BackendProvider (just print a line before exec)
- `Layout` references
- `WezTermSession`/`SessionState`/`PaneRole` imports
- `attach()` function entirely

**Remove from CommonConfig:**
- `layout: Layout`
- `use_wezterm: bool`

### 3. Rewrite vmux-cli

**New subcommands:**
- `vmux run [-- command...]` — resolve secrets, build sandbox, exec into it
  - Default command: `$SHELL` or `bash`
  - `--tool claude|aider|codex` sets the command
  - `--editor nvim|hx|emacs` sets the command
  - Can also pass arbitrary command after `--`
- `vmux config` — print resolved config as JSON (replaces `--dry-run`)

**Drop subcommands:**
- `vmux attach` — was WezTerm-only
- `vmux list` — was microvm-only (keep if microvm backend stays)
- `vmux stop` — was microvm-only (keep if microvm backend stays)

**Drop CLI args:**
- `--layout` — no more pane layouts
- `--no-wezterm` — no more WezTerm
- `--reuse` — was for VM reattach

**Drop from LaunchConfig:**
- `layout`, `use_wezterm` fields
- Keep `--ephemeral` (still useful for VM cleanup)

**Drop from vmux.toml:**
- `[layout]` section

### 4. Keep as-is
- `vmux-sandbox` — core value, no changes needed
- `vmux-secrets` — clean, no changes needed
- `vmux-nix` — thin wrapper, fine as-is

### 5. Exec mechanism

For **bwrap**: use `std::os::unix::process::CommandExt::exec()` to replace the
vmux process with bwrap. The user's terminal becomes the sandbox shell directly.
stdin/stdout/stderr pass through. Ctrl-C works. No polling.

For **microvm**: exec `ssh -t root@<ip> 'source secrets; cd /workspace; <cmd>'`.
Same idea — vmux becomes the SSH session.

This means running two tools side by side is:
```
# Terminal 1
vmux run --tool claude

# Terminal 2
vmux run --editor nvim
```

The user's existing multiplexer (tmux, WezTerm splits, tiling WM) handles layout.
